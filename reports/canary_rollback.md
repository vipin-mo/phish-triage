# The canary stops a bad deployment

Generated by `make rollback-check` on 2026-11-12. A deliberate deployment of the scan function's version 8, which loads an older bundle than the pinned `with-visible-20261112-ac59a4e3`, started from version 9 the way a real release is.

| | |
|---|---|
| Deployment | Failed |
| CodeDeploy's error | HOOK_EXECUTION_FAILURE |
| Rolled back by CodeDeploy | yes |
| `live` alias before / after | version 9 / version 9 |
| Traffic sent to the bad version | none |

The smoke hook (`lambda_handler.before_traffic`) failed the version before any traffic moved. Its log line: version 8 passed the two smoke emails, loaded `with-normalized-20261105-8baede93`, and was failed as "not the pinned bundle"; without the version check it would have gone on to the 10% window. This shows the hook's stop and CodeDeploy's rollback; the alarm-driven rollback during the 10% window hasn't had to run, and with one user that window often gets no scans.
